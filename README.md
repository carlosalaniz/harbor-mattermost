# Mattermost for Harbor

A [Harbor](https://github.com/carlosalaniz/harbor) app: Mattermost Team Edition 11.5.1 with
PostgreSQL 15 (pgvector image), both pinned by digest. Uploaded files live in the app's own
`data` volume (local file storage), so they sit in Harbor's app home with everything else.

```
harbor/            the Harbor package (manifest.yaml + compose.yaml)
```

## Install

In Harbor: **App Store → Your own app → git repository** with this repository's HTTPS URL and
branch `main` (or `harbor sources add https://github.com/carlosalaniz/harbor-mattermost --branch main`),
then install **Mattermost**. Open it and create the first account: it becomes the System Admin.
Email (SMTP) is set in System Console → Environment → SMTP and kept in `config.json`.

## How it runs

| Service | Role |
|---|---|
| `mattermost` | Mattermost server on port 8065; health `/api/v4/system/ping` |
| `mattermost-db` | PostgreSQL 15 (`pgvector/pgvector:pg15`), user and database `mattermost` |

- **Database password**: generated by Harbor (`db-password`), handed to Postgres as
  `POSTGRES_PASSWORD` and to Mattermost as `PGPASSWORD`. `MM_SQLSETTINGS_DATASOURCE` is
  `postgres://mattermost@mattermost-db:5432/mattermost?…` with no password in it: Mattermost's
  Postgres driver reads `PGPASSWORD` (the image has no shell, so the URL cannot be assembled at
  start). Nothing secret lives in this repository.
- **Site URL**: `MM_SERVICESETTINGS_SITEURL` is Harbor's main address for the app
  (`configuration`, origin form), rewritten on install, update and Restart.
- **File storage**: `MM_FILESETTINGS_DRIVERNAME=local`, `MM_FILESETTINGS_DIRECTORY=/mattermost/data/`.
  Environment settings win over `config.json` and show as read-only in the System Console.

| Volume | Mounted at |
|---|---|
| `db` | `/var/lib/postgresql/data` |
| `config` | `/mattermost/config` |
| `data` | `/mattermost/data` |
| `logs` | `/mattermost/logs` |
| `plugins` | `/mattermost/plugins` |
| `client-plugins` | `/mattermost/client/plugins` |
| `bleve` | `/mattermost/bleve-indexes` |

## Moving an existing Mattermost in

Service names match the usual Compose stack (`mattermost`, `mattermost-db`), so a copied
`config.json` and database start as they are. With the Harbor app stopped:

1. Copy the old Postgres 15 data directory into `db`, and `config`, `plugins`, `client/plugins`,
   `bleve-indexes`, `logs` into their volumes (`cp -a`, ownership kept).
2. Files: copy the old data directory into `data`; files kept in S3/MinIO are mirrored with
   `mc mirror <alias>/<bucket> <data volume>` (object keys are the same paths local storage uses).
3. Start the database only. If the old role/database are not named `mattermost`, rename them
   (`ALTER ROLE old RENAME TO mattermost; ALTER DATABASE old RENAME TO mattermost;` from a
   temporary superuser, since a session cannot rename its own role), or change the literals in
   `harbor/compose.yaml` together.
4. Set the role's password to Harbor's `db-password` (`ALTER ROLE mattermost PASSWORD …`) and
   start the app. Logins, posts and attachments carry over; `config.json` may keep an old
   `amazons3` driver, the environment overrides it to `local`.
